# 金融資產價格資料的處理（對數報酬與必做清單）

本檔是 SKILL.md 第 1 階段「特例：金融資產價格資料」的細節。確認資料是股價、指數、匯率、加密貨幣收盤價等金融資產價格時讀本檔。

## 預設轉成對數報酬（log return）

只要確認資料是**股價（或任何價格型／指數型資產序列，如指數、匯率、加密貨幣收盤價）**，
就**預設先轉成對數報酬再分析，不直接對原始價格做 EDA 與檢定**，並**告訴使用者理由：通常是報酬率才能拿來做時間序列分析；價格只在特定情境（例如共整合、配對交易的長期關係）才會直接用來分析**。
原始價格幾乎必然非平穩、變異數隨價位放大，且會誤導趨勢與季節判讀；對數報酬則接近平穩、可加總、對應連續複利，是金融時序的標準做法。
（使用者明確要分析價格水準本身時才例外，見下方。）

```r
# 對數報酬：r_t = log(P_t) - log(P_{t-1}) = log(P_t / P_{t-1})
returns <- diff(log(price))          # ts / 向量
# tsibble 版（使用者選用 tsibble 時）：
tsbl <- tsbl |> mutate(log_return = difference(log(close)))
```

轉換後的注意事項：

- **轉換後要把「對數報酬」當成新的分析對象，完整重跑 EDA——不可只做轉換就跳過基本 EDA**
  （這是實際產出的報告最常漏掉的一塊）。對「對數報酬」**至少要有下列，缺一不可**：
  1. **報酬的時間圖**（原始價格圖保留一張供對照即可）。
  2. **五數統計**（最小值、下四分位 Q1、中位數、上四分位 Q3、最大值，用 `fivenum()` 或 `summary()`）
     **與箱形圖 `boxplot()`**，看報酬的分布形狀與離群。
  3. **六項摘要表**（mean、sd、skewness、excess kurtosis、min、max，對百分比報酬），見下方程式碼。
  4. **`ACF(報酬)` 與 `ACF(報酬^2)`** ＋ `FinTS::ArchTest()`，看自相關與波動聚集。
  5. **平穩性檢定：ADF 與 KPSS 兩者都做**（設定選擇與四種情況判讀見第 5 階段；報酬通常無趨勢、圍繞某個水準波動，多半用 c 設定）。
     報酬通常已近似平穩、多半不需再差分，但**仍要真的把兩個檢定跑出來、把統計量與 p 值寫進報告**（用來「確認」而非省略）。
- 金融報酬常見**波動聚集（volatility clustering）**：報酬本身自相關低，但報酬**平方**或**絕對值**的 ACF 會顯著。
  EDA 時可多畫一張 `ACF(報酬^2)`，並用 `FinTS::ArchTest()`（Engle's LM test）正式檢定是否存在 ARCH 效果來揭示這點。
  這是後續 **GARCH 類模型**（`rugarch`／`fGarch::garchFit()`）的線索，細節見 `references/arima-garch-bridge.md`。
- **必做：報酬的敘述統計摘要表。** 對**百分比對數報酬**（報酬 ×100）計算六項並用 flextable 出表：
  **樣本平均數（mean）、標準差（sd）、偏態（skewness）、超額峰態（excess kurtosis）、最小值（min）、最大值（max）**。
  這是金融報酬的標準 EDA：報酬近似零均值，**偏態看不對稱、超額峰態看厚尾**，正是報酬的典型特徵，也是要不要上 GARCH 的線索。

```r
library(fpp3); library(e1071); library(flextable)
pct <- as.numeric(returns) * 100                      # 百分比對數報酬
summ <- tibble::tibble(
  統計量 = c("平均數", "標準差", "偏態", "超額峰態", "最小值", "最大值"),
  數值   = c(mean(pct), sd(pct),
             e1071::skewness(pct), e1071::kurtosis(pct),   # kurtosis() 預設回傳「超額」峰態
             min(pct), max(pct))
)
flextable(summ) |> colformat_double(digits = 4) |> ft_fit(summ)
```

- **取得資料（選用）**：若使用者沒有現成 CSV，可用 `quantmod` 從 Yahoo Finance 抓（資料到最近交易日）：

```r
library(quantmod)
px <- getSymbols("2330.TW", src = "yahoo", from = Sys.Date() - 3 * 365, auto.assign = FALSE)
close <- Ad(px)          # 用調整後收盤價（還原除權息），才適合算報酬
```

  提醒：**一律用調整後收盤價 `Ad()`**；Yahoo 偶有缺漏或含 NA 的交易日，抓下來要先做健康檢查；
  代碼慣例：台股 `2330.TW`、台積電 ADR `TSM`、美股直接用代碼（`AAPL`）。這只是取數管道，非硬相依。
- 若使用者明確要分析的是「價格水準」本身（例如做共整合、配對交易的長期關係），才例外保留原始價格，並在報告註明理由。

**先判斷這是什麼類型的資料，並把目前的判斷告訴使用者**（依欄位名稱如 close、price、adj_close…、數值特性與使用者說明）；無法判斷時，先問使用者這是什麼類型的資料。
**確認是金融資產價格資料**（股價、指數、匯率、加密貨幣收盤價等）時，**預設轉成對數報酬**，並告訴使用者理由：通常是報酬率才能拿來做時間序列分析；價格只在特定情境（例如共整合、配對交易的長期關係）才會直接用來分析，使用者若屬這類情境則依上一條例外處理。**不是價格資料就不提這題。**
